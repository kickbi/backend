# Course Generation Reference

This document explains the full schema and the pattern for writing a new course seeding script in KickBi. Every course is generated by calling a single `generate<CourseName>Course()` async function that creates the MongoDB documents in the correct hierarchy.

---

## Hierarchy

```
Subject
  └── Course          (belongs to one or more Subjects)
        └── Chapter   (ordered list, stores TopicsCount)
              └── Topic (ordered list; THEORY type has Content, QUIZ type has Question)
```

Lessons have been removed. Topics are children of Chapters directly. Every entity carries an embedded `SEO` subdocument that the course API returns as-is so the frontend can populate all `<head>` tags and JSON-LD from a single response.

---

## Schema Reference

### SeoSchema (`_seo.schema.ts`)

Embedded (no `_id`) into Subject, Course, Chapter, and Topic.

| Field           | Type   | Notes                                                                           |
| --------------- | ------ | ------------------------------------------------------------------------------- |
| Slug            | String | URL-friendly identifier (e.g.`schrodinger-equation`)                          |
| MetaTitle       | String | `<title>` tag content — 50-60 chars recommended                              |
| MetaDescription | String | `<meta name="description">` — 150-160 chars recommended                      |
| OgTitle         | String | `og:title` Open Graph tag                                                     |
| OgDescription   | String | `og:description` Open Graph tag                                               |
| OgImage         | String | S3 key for `og:image`; resolved to a full URL by the API                      |
| CanonicalUrl    | String | Relative path for `<link rel="canonical">`; frontend prepends the base domain |
| JsonLd          | String | Serialised JSON-LD (`JSON.stringify(...)`) for schema.org structured data     |

Indexes:

- Subject: `{ "SEO.Slug": 1 }` — unique, sparse
- Course: `{ "SEO.Slug": 1 }` — unique, sparse
- Chapter: `{ CourseId: 1, "SEO.Slug": 1 }` — unique, sparse
- Topic: `{ ChapterId: 1, "SEO.Slug": 1 }` — unique, sparse

### RawContent Tag System

`RawContent` uses a custom XML-style tag system — **not** Markdown. The frontend parses these tags to render headings, paragraphs, lists, code, and math.

#### Block tags

| Tag                                 | Usage                                        |
| ----------------------------------- | -------------------------------------------- |
| `[H:H2] text [/H:H2]`             | Section heading (equivalent of `<h2>`)     |
| `[H:H3] text [/H:H3]`             | Sub-section heading (equivalent of `<h3>`) |
| `[P] text [/P]`                   | Paragraph                                    |
| `[UL] [LI] item [/LI] [/UL]`      | Unordered (bullet) list                      |
| `[OL] [LI] item [/LI] [/OL]`      | Ordered (numbered) list                      |
| `[BLOCK:CODE] code [/BLOCK:CODE]` | Multi-line code block                        |

#### Inline tags (used inside `[P]`, `[LI]`, etc.)

| Tag                     | Usage                                         |
| ----------------------- | --------------------------------------------- |
| `[B] text [/B]`       | Bold / emphasis                               |
| `[SPAN] text [/SPAN]` | Inline highlight / styled span                |
| `[CODE] text [/CODE]` | Inline code or variable name                  |
| `[MATH] expr [/MATH]` | Inline or block math expression (KaTeX-style) |

#### Content markers (kept as-is, on their own line between block tags)

| Marker             | Resolved by the frontend to                          |
| ------------------ | ---------------------------------------------------- |
| `[EXAMPLE:Name]` | The matching `Examples[]` entry by `ExampleName` |
| `[HINT:Name]`    | The matching `Hints[]` entry by `HintName`       |
| `[ASSET:Name]`   | The matching `Assets[]` entry by `AssetName`     |

These markers are **not** wrapped in other tags — they stand alone on their own line.

**Example snippet:**

```
[H:H2] Why Classical Physics Breaks Down [/H:H2]

[P] For large objects, [B] Newton's laws [/B] predict exact paths. [/P]

[P] For an electron, the wavelength is [MATH] \lambda = h / p [/MATH], which is large enough to cause interference. [/P]

[HINT:DoNotSearchForOnlyOnePath]

[UL]
[LI] Large objects: path-based motion [/LI]
[LI] Tiny particles: wave-like behavior [/LI]
[/UL]
```

### AIExplanation (`aiexplanation.model.ts`)

Standalone collection. Each document holds one version of a bilingual explanation.

| Field    | Type   |
| -------- | ------ |
| English  | String |
| Hinglish | String |

`AIExplanationVersionIds` arrays on Course, Chapter, ContentSchema, and QuestionsSchema are ObjectId refs to this collection. The API picks one at random per request so users see variety.

## SEO Field Usage by the Frontend

When the course API returns a document, the frontend reads:

| SEO field       | Frontend usage                                       |
| --------------- | ---------------------------------------------------- |
| MetaTitle       | `<title>` and `<meta property="og:title">`       |
| MetaDescription | `<meta name="description">` and `og:description` |
| OgTitle         | `<meta property="og:title">` override if present   |
| OgDescription   | `<meta property="og:description">` override        |
| OgImage         | `<meta property="og:image">` (S3 URL)              |
| CanonicalUrl    | `<link rel="canonical" href="base+CanonicalUrl">`  |
| JsonLd          | `<script type="application/ld+json">`              |
| Slug            | URL routing —`/courses/:slug`, `/topics/:slug`  |

No additional API calls are needed. One course GET response contains SEO data for the course, its chapters, and all topics.

## AI Explanation Version Styles

Write exactly **5 versions** per location. Think of each version as a different teaching style:

| Version | Style                        |
| ------- | ---------------------------- |
| 1       | Conceptual / intuition-first |
| 2       | Analogy-based                |
| 3       | Step-by-step / structured    |
| 4       | Common mistake correction    |
| 5       | Summary / recap style        |
